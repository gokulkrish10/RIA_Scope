### Exact read-only checks and API examples

Use this after the scheduled-run step to prove a *new* job on the isolated copy (record the prior latest ID before changing the interval):

```sh
python3 - <<'PY'
import sqlite3
c = sqlite3.connect('file:.data/manual-rbi-demo/ria.sqlite?mode=ro', uri=True)
for row in c.execute("SELECT j.id,j.state,j.created_at,rs.source_id FROM jobs j JOIN monitoring_run_sources rs ON rs.job_id=j.id WHERE j.kind='monitor' ORDER BY j.created_at DESC LIMIT 5"):
    print(row)
c.close()
PY
```

Exact authenticated gateway requests can be inspected in browser DevTools Network: `GET /api/v1/sources`, `GET /api/v1/publications?page=1&pageSize=1`, `GET /api/v1/publications/1d94a2af-7aeb-447a-906a-cf86ca79f35d`, `GET /api/v1/publications/1d94a2af-7aeb-447a-906a-cf86ca79f35d/obligations`, and `GET /api/v1/comparisons/5dda2072-ce8b-4dbf-b152-2939f5c6e5ee`. Pagination response should have one `items` entry, `total: 2` before manual uploads, and `hasNextPage: true`. Manual `POST /api/v1/monitor-runs` uses `{ "sourceIds": ["a9a3a4fa-9339-4db5-ae97-57a99fcaf0fa"] }`; poll `GET /api/v1/jobs/:jobId`, then `GET /api/v1/monitor-runs/:jobId/result`. Upload uses multipart fields **`file`** and **`metadata`**, returns 202, then poll its ingestion job. Review uses `PATCH /api/v1/publications/:publicationId/review` with `state`, `note`, and the current detail's `review.updatedAt` as `expectedUpdatedAt`; the browser never sends reviewer identity.
