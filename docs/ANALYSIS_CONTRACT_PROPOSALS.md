# Analysis contract coordination notes

The shared v1 schemas remain unchanged. These gaps were identified before implementing analysis and must be coordinated with Sethu before adding public fields/endpoints:

1. **Separate analysis trigger/state.** There is no structured-analysis endpoint or job kind, and processingState currently describes ingestion/extraction. Analysis is queued automatically after text extraction (disable with `RIA_ANALYSIS_ENABLED=false`), and a trusted local CLI can enqueue analysis of an already ingested version using the existing ingestion job kind. The original ingestion job remains a text-stage result; read current publication processing state and obligations for structured readiness. Do not invent a frontend analysis route. A future coordinated extension should add a version-targeted analysis request, discoverable analysis job ID and its own state dimension.
2. **Document/requirement status.** There is no documentStatus or proposed/mandatory obligation field. Store the model's cited status internally; preserve `kind: consultation` in public metadata and prefix proposed obligation text with `Proposed requirement: `. Never present consultation requirements as enacted. Proposed future additions: `documentStatus` and `requirementStatus` with explicit unknown/null semantics. Until agreed, non-consultation proposed/withdrawn status must also be stated in the summary/text, not hidden behind an effective-date guess.
3. **Highlight fragments.** ChangeItem already returns exact before/after excerpts. A browser-safe deterministic helper can compute highlights without changing JSON. Sethu should import that helper and render escaped text, never raw HTML. Persist the same computed fragments with the comparison internally. A server-supplied `diff` field is a future coordinated option.
4. **Unresolved clause evidence.** v1 blocked comparisons only support missing/ambiguous predecessor reference IDs. If a predecessor is known but supported clause pairs cannot be established, use an explicit failed comparison with `comparisonFailed`, explain the missing evidence, and require review; never emit `noMaterialChange`. A future coordinated `insufficientEvidence` issue/state could distinguish this from technical model failures.
5. **Relationship operations.** Use existing publication detail `references`/`relationshipState` for reads, and the existing `/publications/:publicationId/predecessor` operation for explicit links and reruns. There is no separate relationships endpoint to invent.

These notes do not change shared schemas. The user approved additive SQLite migrations; 002 and 003 add analysis persistence and version locks without rebuilding existing tables. Source-adapter ownership remains: Gokul owns ingestion/worker and the existing isolated CBK adapter; Sethu's adapters have not started. Coordinate additional region adapters with Sethu before either side implements duplicates.
